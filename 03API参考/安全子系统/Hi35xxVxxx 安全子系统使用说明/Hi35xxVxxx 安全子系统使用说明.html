        概述

        芯片提供丰富的安全特性，包括一系列硬件、固件和软件，以支持客户构建安全可信的设备。主要的安全特性如下：

        • 支持One Time Programmable（OTP），用于存储包括设备安全启动验签的ECC 公钥哈希、多组对称根密钥、SoC安全相关的各种控制信息，以及用户自定义数据等。
        • 支持基于OTP对称根密钥进行密钥派生。支持对烧录到OTP的根密钥的加扰保护；密钥派生过程中所有的明文密钥软件不可见。派生后的明文密钥可送给对称密码算法加速器进行安全的密码计算。
        • 支持硬件真随机数。
        • 支持RSA, ECC, SM2等非对称密码算法的加速。
        • 支持AES, SM4等对称密码算法的加速。
        • 支持SHA2, SM3等杂凑密码算法的加速。
        • 支持基于硬件可信根的安全启动：支持安全镜像逐级校验；支持镜像加密可选择；支持TEE/REE信任链分离；安全启动镜像和非安全启动镜像格式统一，即安全启动没有使能的情况下，非加密的安全启动镜像也可以正常启动。
        • 支持ARM TrustZone，支持安全、非安全内存地址隔离。客户可构建TEE安全方案。
        • 支持JTAG分级保护。

        简介

        OTP是一种非易失性存储器，其主要特性是对应存储空间的内容由0写为1之后，或者写入后锁定，就不能再次更改。 OTP 包含如下几大区域：

        1. 存放SoC各种密钥的区域：包括存放安全启动的根公钥哈希值(受限可读），存放保护多个对称密码算法根密钥。密钥区域一旦发起写入操作，自行锁定不可再更改。

          芯片可存放各组根公钥哈希值，用于安全启动校验。包括：芯片厂商根公钥哈希(已预置），OEM根公钥哈希和第三方双签名根公钥哈希。客户可根据产品实际需要，选择合适的根公钥（通过OTP选择）。

          加解密根密钥：芯片预留OEM可烧写的对称密码根密钥OTP空间，如：Hi3516CV610 和 Hi3511CV100 中预留 oem_rootkey OEM可以利用这里面的一个或者多个根密钥，分别派生出不同的密钥保护密钥和工作密钥。这些密钥区域可以通过对应的OTP烧写接口烧写，一旦写入，硬件自行锁定，不可更改。写入的内容也不能通过软件方式或JTAG接口读取得到。

          芯片预置一个芯片厂商TEE对称密码算法加解密的根密钥，用户可根据实际需要选择使用（通过OTP选择）。

        2. SoC重要特性/功能开关控制区域（含单bit控制区域和多bit控制区域）：SoC大多数重要的特性，都可以通过OTP来控制，以提高产品应用的灵活性。比如：安全启动使能，安全启动镜像是否加密，安全启动是否启动冗余备份，是否使能TEE等等。特性/功能开关控制区域，在烧写好目标值之后，都可以选择将其锁定，避免后续非法篡改。建议客户在最终产品发布前，将所有的特性/功能开关位对应的值设置好，并按需锁定。

        3. 用户自定义区域（仅Hi3519DV500支持）：芯片集成了约25Kbit的用户自定义OTP区域，用以存放用户数据。

          用户自定义区域还包含了一个128bit的版本控制区域：版本控制区域用于存放重要版本标识，防止版本回滚攻击。即防止攻击者利用有安全漏洞的老的合法镜像重新升级，实现重放攻击。版本控制区域不能锁定，每一个控制位都只能由0写到1，一旦写入1后，便不可再更改（one way 模式）。

          在 SDK 包中，提供了OTP相关的读写接口。详细请参考本文“OTP字段定义”以及文档《安全子系统 API 参考》。

          须知：
          - 所有的OTP控制位，无论默认值是否满足实际应用，请全部重新烧写锁定，保证设备安全。
          - 文档中未列出的OTP控制位不代表是保留可用的，有可能已经被芯片厂商用于可靠量产等目的，不可随意烧写。
          - OTP 仅在重新上电或看门狗复位后生效。U-Boot 下已提供看门狗复位命令即 dog_reset 命令。

        LOCK属性说明
        • Oneway属性：具有此属性的位域未烧写为1的bit都可以在下一次继续烧写，直到所有bit都烧为1；lock使能位不会锁定此属性的位域；
        • lockable属性：lockable属性的相关位域在锁定前与oneway属性一致，烧写对应的lock位后，即使没烧写过的bit也不能再次烧写；建议lockable属性的位域，烧写值后对对应的位域进行锁定，防止被修改。
        Load shadow属性说明

        Y：芯片上电硬复位后OTP的值会自动加载到对应的寄存器（shadow寄存器）；shadow寄存器区域有自己的基地址，而偏移地址与OTP fuse所在的OTP memory地址完全一致。每次烧写OTP后，必须重新上下电才能从shadow寄存器读到刷新后的值；

        N：OTP位域无对应的shadow寄存器。

        安全启动

        Hi35xxVxx 支持基于芯片硬件可信根的安全启动。支持对U-Boot，TEE OS进行验签，加解密。内核镜像和文件系统的验签和加解密可在U-Boot中定制化修改。支持OEM和第三方双签名。芯片OTP中存储public key的hash值作为安全启动签名校验的起点（可信根）。OTP中的可信根以及数据加解密根密钥完全由客户自行管理并烧录，并受硬件保护，软件不可读写。

        安全启动流程分为两部分，一部分固化在芯片内，称为BOOTROM；一部分在软件中实现，称为Secure BOOT或GSL。BOOTROM流程不可篡改。GSL由BOOTROM验签，GSL流程安全性由BOOTROM保证。GSL负责实现对后续镜像的验签功能，进而保证全部启动通路的安全性。

        强烈建议在产品开发中使用安全启动。安全启动更详细的信息，请参考文档《Hi35xxVxx 安全启动使用指南》。

        2. 编写增熵用的用户态程序。以下为伪代码实现流程，是一种通用的增熵方法，如有其他高质量熵源，同样可以使用类似的方法为内核快速补熵：

          /*
 The value can be obtained by reading the
 /proc/sys/kernel/random/poolsize file, and
 its unit is in bits.
*/
Define constant MAX_ENTROPY_POOL_SIZE as 256

/*
 Please ensure that this value multiplied by 8 is
 greater than or equal to MAX_ENTROPY_POOL_SIZE,
 and the unit of this value is in bytes.
*/
Define constant MAX_RANDOM_BUF_SIZE as 32

Define structure entropy {
    Integer variable entropy_count
    Integer variable buf_size
    Byte buffer pointer buf
}

Function main() {
    Define integer variables ret, hwrng_fd, rand_fd
    Define integer variable rd
    Define structure variable ent
    Define byte buffer buf[with size MAX_RANDOM_BUF_SIZE]

    Set ent.entropy_count to MAX_ENTROPY_POOL_SIZE
    Set ent.buf_size to MAX_RANDOM_BUF_SIZE
    Set ent.buf to the address of buf

    Open file "/dev/random" in write mode, store file descriptor in rand_fd
    If rand_fd < 0, then {
        Output error "Failed to open /dev/random!"
        Exit the program
    }

    Open file "/dev/hwrng" in read mode, store file descriptor in hwrng_fd
    If hwrng_fd < 0, then {
        Output error "Failed to open /dev/hwrng!"
        Close rand_fd
        Exit the program
    }

    Read MAX_RANDOM_BUF_SIZE bytes from hwrng_fd into buffer buf, save the number of bytes read into rd
    If rd < 0, then {
        Output error "Failed to read /dev/hwrng!"
        Close rand_fd
        Close hwrng_fd
        Exit the program
    }

    Perform ioctl operation, add bytes from buffer buf to the entropy pool, command is RNDADDENTROPY
    If ret < 0, then {
        Output error "Failed to add entropy to the pool!"
        Close rand_fd
        Close hwrng_fd
        Exit the program
    }

    Close hwrng_fd
    Close rand_fd

    Output "Entropy added successfully."

    Return 0
}

          上述伪代码的工作流程可概括为两步，第一步从/dev/hwrng节点获取高质量熵，第二步通过对/dev/random节点进行IOCTL将熵补充进熵池。以下为伪代码的一种参考示例：

          #include <linux/random.h>
#include <unistd.h>
#include <stdio.h>
#include <fcntl.h>
#include <stdlib.h>
#include <sys/ioctl.h>

/*
 The value can be obtained by reading the
 /proc/sys/kernel/random/poolsize file, and
 its unit is in bits.
*/
#define MAX_ENTROPY_POOL_SIZE 256

/*
 Please ensure that this value multiplied by 8 is
 greater than or equal to MAX_ENTROPY_POOL_SIZE,
 and the unit of this value is in bytes.
*/
#define MAX_RANDOM_BUF_SIZE 32

typedef struct entropy {
    int entropy_count;
    int buf_size;
    unsigned char *buf;
} entropy;

int main()
{
    int ret, hwrng_fd, rand_fd;
    ssize_t rd;
    struct entropy ent;
    unsigned char buf[MAX_RANDOM_BUF_SIZE];

    ent.entropy_count = MAX_ENTROPY_POOL_SIZE; 
    ent.buf_size = MAX_RANDOM_BUF_SIZE;
    ent.buf = buf;

    rand_fd = open("/dev/random", O_WRONLY);
    if (rand_fd < 0) {
        perror("Failed to open /dev/random!\n"); 
        exit(1);
    }
    hwrng_fd = open("/dev/hwrng", O_RDONLY);
    if (hwrng_fd < 0) {
        perror("Failed to open /dev/hwrng!\n");
        close(rand_fd);
        exit(1); 
    }

    // read MAX_RANDOM_BUF_SIZE bytes from /dev/hwrng
    rd = read(hwrng_fd, buf, MAX_RANDOM_BUF_SIZE);
    if (rd < 0) {
        perror("Failed to read /dev/hwrng!\n");
        close(rand_fd);
        close(hwrng_fd);
        exit(1);
    }

    // add bytes to the entropy pool
    ret = ioctl(rand_fd, RNDADDENTROPY, &ent);
    if (ret < 0) {
        perror("Failed to add entropy to the pool!\n");
        close(rand_fd);
        close(hwrng_fd);
        exit(1);
    }

    close(hwrng_fd);
    close(rand_fd);
    printf("Entropy added successfully.\n");

    return 0;
}

        MbedTLS 开源软件是一款开源的轻量级加密库，其提供了一系列密码学和安全协议的实现，包括对称加密、非对称加密、散列函数、消息认证码、数字签名、密钥交换、安全套接层（SSL/TLS）以及 X.509 证书管理等。MbedTLS 具有简洁、可移植和易于使用的特点，具备高度优化的性能和低资源消耗，被广泛应用于资源受限的嵌入式设备和应用程序中。Hi35xxVxx 基于 MbedTLS 开源软件提供了一些安全算法的硬件实现，其底层调用安全子系统驱动和专用硬件进行硬化加速，提供高算法计算性能的同时，减少了 CPU 的计算开销。该硬化方案提供的接口和MbedTLS原生接口一致，无附加学习成本。

        如需使用，需自行安装开源软件至服务器。

        Linux Crypto硬化加速

        Linux Crypto是linux内核中用于提供加密、解密、哈希计算、消息认证码（MAC）生成等密码学相关操作的子系统。它为用户空间程序和内核自身的组件提供了统一的密码学接口，使得在 Linux 系统中能够方便、安全地使用各种密码学算法。通过内核提供的注册接口，将硬件驱动对接到linux crypto框架，提供高算法计算性能的同时，减少了 CPU 的计算开销。当前支持AES-CBC、CTR、CCM、GCM模式和SHA256（Hi3519DV500支持SHA384/SHA512）的硬化加速。

        利用开源软件cryptodev-linux可将内核加解密接口导出到用户态，供应用程序使用。如何使用请参考security_subsys/hardware_cryptodev目录下的readme_cn.txt。

        TZASC

        Hi35xxVxx 提供TZASC模块，支持对内存地址空间进行隔离控制，使CPU和其他SoC组件在处于安全模式和非安全模式等不同特权模式下，对内存的访问权限进行硬件级别的控制。这是实现基于ARM TrustZone 下的TEE、REE隔离的基础。

        TZASC全称是TrustZone Address Space Controller，它是Advanced Microcontroller Bus Architecture（AMBA）兼容的SoC外围组件，可对接AMBA AXI和AMBA APB接口。

        Hi3519DV500的TZASC模块提供了16个区域，其中15个区域可配（region1~region15）。region0固定使能，无法配置访问属性，大小覆盖除了region1~region15区域以外的所有内存区域。任何组件（无论是安全还是非安全）都无法访问region0覆盖的内存。

        其余内存区域的访问属性，可以根据需要，选择下面四个属性单元的组合：

        • 安全可读属性
        • 安全可写属性
        • 非安全可读属性
        • 非安全可写属性

        TZASC模块的bypass属性控制着模块是否使能：

        • 默认bypass属性使能，TZASC模块处于失能状态，内存访问不受限制；
        • 设置bypass属性失能，TZASC模块将会使能，各内存区域的访问属性生效。

        TZASC控制的参考代码，请参考发布包GSL源代码根目录下drivers/tzasc/tzasc.c，该代码在boot/checkup.c中调用。

        须知：
        - bypass属性使能被锁定之后，在系统复位前无法再次使能鉴权功能。
        - TZASC的配置，建议客户在系统启动之后，只做一次配置，不要多次动态调整，以避免处理不当导致其他异常。
        - Hi3511CV100不涉及TZASC。

        FUNC JTAG

        说明：
        Hi3516CV610不支持FUNC JTAG密码保护模式。
        FUNC JTAG即为功能JTAG，用于在功能模式下调试SoC的JTAG接口。

        芯片的FUNC JTAG调试接口可以通过OTP进行打开模式、密码模式、永久关闭模式的切换，默认为打开模式。OTP烧写的具体操作方法，请参照本文“OTP字段定义”和文档《安全子系统 API 参考》。

        通过JTAG调试接口对SoC进行调试，需要配套的调试板和PC对应的软件工具。

        JTAG的模式由OTP中的func_jtag_mode来控制。

        • 0x42：打开，即无需任何权鉴即可连通JTAG；此状态为芯片出厂的状态。
        • 0x63：密码保护模式，需要输入正确的芯片唯一JTAG密码才可连通JTAG；JTAG密码为一机一密，由硬件KDF自动根据obfu_mrk1和die_id派生，obfu_mrk1由OEM生成并管理，其值仅OEM可知；输入JTAG 密码前需要获取芯片的die_id，再使用KDF派生工具即可派生出对应的JTAG密码。
        • 其他：jtag关闭，即不可用。

        注意：
        func_jtag_mode具有oneway属性，即一旦烧写为密码保护状态或者关闭状态，就永久不能回退到打开状态，也就意味着永久将JTAG调试功能禁用，烧写前需要注意。
        FUNC JTAG保持打开会给最终产品引入严重的安全风险，强烈建议在最终出厂前烧写为密码保护模式或者关闭模式。

        DFT JTAG

        说明：
        Hi3516CV610不支持DFT JTAG密码保护模式。
        DFT JTAG即为测试JTAG，用于在测试模式下对SoC灌入测试向量，执行芯片筛片测试和失效分析测试的JTAG接口。

        芯片的DFT JTAG调试接口可以通过OTP进行打开模式、密码模式、永久关闭模式的切换，默认为打开模式。OTP烧写的具体操作方法，请参照本文“OTP字段定义”和文档《安全子系统 API 参考》。

        通过JTAG调试接口对SoC进行调试，需要配套的调试板和PC对应的软件工具。

        JTAG的模式由OTP中的dft_test_jtag_mode来控制。

        • 0x42：打开，即无需任何权鉴即可连通JTAG；此状态为芯片出厂的状态。
        • 0x63：密码保护模式，需要输入正确的芯片唯一JTAG密码才可连通JTAG；JTAG密码为一机一密，由硬件KDF自动根据obfu_mrk0和die_id派生，obfu_mrk0由芯片厂商生成并管理，其值仅芯片厂商可知；输入JTAG 密码前需要获取芯片的die_id，再使用KDF派生工具即可派生出对应的JTAG密码。
        • 其他：jtag关闭，即不可用。

        注意：
        dft_test_jtag_mode具有oneway属性，即一旦烧写为密码保护状态或者关闭状态，就永久不能回退到打开状态，也就意味着永久将芯片失效分析测试功能禁用，烧写前需要注意。
        DFT JTAG保持打开会给最终产品引入一定的安全风险，考虑到DFT JTAG保护密码和DFT JTAG向量仅由芯片厂商掌握，因此其安全风险没有FUNC JTAG高，但仍建议OEM在明确没有复测需求的场景下将DFT JTAG烧写为关闭模式。
