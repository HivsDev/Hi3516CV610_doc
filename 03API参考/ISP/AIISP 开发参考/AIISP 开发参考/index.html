    AIBNR概述

    AIBNR（AI-based Bayer Noise Reduce）是一种新型的去噪算法，它能使成像设备在更低照度时噪声去除更干净，细节保留更多，从而提高成像设备极低照度的感光能力。本文主要介绍AIBNR的接口说明和使用注意事项。

    AIBNR参考帧普通模式性能支持3072 x 1728@30fps，无参考帧模式支持3072 x 1728@40fps。Hi3516CV610最大支持2688 x 1520@12fps。

    说明：
    Hi3516CV608和Hi3516CV610-10B板型不支持AIBNR，初始化和使能接口已做限制。Hi3519DV500和Hi3516CV610其他板型支持AIBNR。

    AIBNR基本概念

    • sfs (spatial filter strength)，即空域去噪强度。
    • tfs (temporal filter strength)，即时域去噪强度。

    AIBNR性能

    性能跟加载的模型相关，详细的性能数据请参考本文档模型列表中的数据。

    AIDRC概述

    AIDRC（AI-based Dynamic Range Compression）是一种基于AI的新型的动态范围压缩算法，它能在宽动态场景下，更好地保留亮暗区（尤其是逆光区域）的细节，同时提升整体对比度，从而提高成像设备在宽动态场景的细节捕获能力。本文主要介绍AIDRC的接口说明和使用注意事项。

    AIDRC NORMAL模式性能支持3840x2160@30fps，ADVANCED模式支持3072x1728@30fps。

    说明：
    Hi3516CV610不支持AIDRC。

    AIDRC基本概念

    • strength：即细节增强强度，值越大，对细节的增强程度越明显。
    • threshold：噪声抑制阈值，值越大，越能够规避对噪声的放大。
    • AIDRC NORMAL模式：仅处理画面细节，资源消耗较小。
    • AIDRC ADVANCED模式：同时处理画面细节和亮度，进一步提升整体对比度，资源消耗稍大。

    AI3DNR概述

    AI3DNR（AI-based 3D Noise Reduce）是一种基于AI的新型的3维降噪算法，它是YUV域的降噪算法。本文主要介绍AI3DNR的接口说明和使用注意事项。

    说明：
    Hi3516CV610不支持AI3DNR。

    AI3DNR基本概念

    • YUV net：表示YUV都经过AI的处理。
    • UV net：表示仅针对图像的UV数据进行AI的处理。

    使能AIBNR数据流开关。

    【语法】

    td_s32 ss_mpi_aibnr_enable(td_s32 pipe);

    【参数】

    参数名称

    描述

    输入/输出

    pipe

    VI模块的PIPE号。

    取值范围：[0, OT_VI_MAX_PHYS_PIPE_NUM)，详见《MPP 媒体处理软件V6.0 开发参考》“视频输入”章节。

    输入

    【返回值】

    返回值

    描述

    0

    成功。

    非0

    失败，请参见错误码。

    【需求】

    • 头文件：ss_mpi_aibnr.h
    • 库文件：libss_mpi_aibnr.a

    【注意】

    • 调用此接口前需要先初始化VI、ISP模块。
    • 同一个pipe，支持与ai3dnr的uvnet同时开启，不支持与aidrc同时开启。
    • 主进程调用该接口前必须先调用ss_mpi_aibnr_init初始化AIBNR模块，并调用ss_mpi_aibnr_load_model接口加载AIBNR模型文件。

    • 其他次进程（例如PQTools）支持使用该接口打开AIBNR数据流，无需初始化AIBNR，但需要主进程保证已经调用了ss_mpi_aibnr_init来初始化AIBNR模块。enable aibnr前有如下限制条件：

      • 对应的vi pipe必须已经创建，且建议使用pipe0，在其他pipe上开启时，PQ效果不是最佳的。
      • 需要用户调用函数去分配VB池，VB大小计算使用函数ot_aibnr_get_pic_buf_size，详见《MPP 媒体处理软件V6.0 开发参考》“系统控制”章节，且分配的VB池需要attach对应的PIPE上。

    • AIBNR使能之后，延迟2帧生效。

    • AIBNR仅支持12bit的Bayer图像数据处理。如果sensor输入非12bit的Bayer图像，需设置VI PIPE输出的图像数据格式为Bayer 12bit。
    • 调用该接口前，需要提前通过ss_mpi_sys_set_vi_aiisp_mode接口配置VI为OT_VI_AIISP_MODE_DEFAULT模式，只支持VI离线。
    • 线性模式下建议在pipe0上使用AIBNR。
    • Hi3516CV610的AIBNR只有pipe0支持，且只支持RGGB pattern，不支持wdr，FPN在AIBNR之后，如果AIBNR和FPN同时开启，可能会影响FPN效果，建议不要同时开启。

    • AIBNR的使用有如下限制：

      • VI的FE和BE之间必须离线，且不支持vi pipe低延时，不支持vi卷绕；
      • vi pipe通路不能开压缩；
      • Hi3519DV500只支持有FE的VI pipe，不支持虚拟VI pipe，不支持VI pipe灌raw。Hi3516CV610不支持VI dev灌raw，支持pipe灌raw，灌raw使用的vb需要来自于aibnr使用的user vb池，且灌raw的帧信息中的isp_frame_info的dgain_agamma_en设置为TD_TRUE。从未开启AIBNR的FE获取的raw，回灌到开启AIBNR的pipe前需要离线将raw做预处理，参考《图像质量调试工具使用指南》“AIBNR向板端倒灌RAW图像”章节。
      • VI PIPE属性需要设置为非压缩、线性格式。

    • 除了以上限制，AIBNR的WDR模式使用有如下限制：

      • 建议在长帧所在的pipe开启AIBNR；
      • 不支持blend模式；
      • 超性能场景可能会出现WDR长短帧丢帧不同步，进而导致WDR融合效果异常。

    • Hi3516CV610 AIBNR处理后，图像四边存在几个像素点的马赛克pattern异常，推荐打开vpss crop功能，上下左右各裁剪8个像素点，可以解决该效果异常问题。

    • Hi3516CV610 AIBNR只支持stride是16的整数倍的图像。
    • Hi3516CV608和Hi3516CV610-10B板型不支持调用。

    • 调用该接口指定使用的模型如果被卸载了，会导致业务异常。

    等于1：重新加载参考帧，收敛速度慢，不会导致画面残影。

    取值范围: [0, 1]，默认值为1。

    motion_gain

    仅支持Hi3516CV610的pro模型。

    运动检测增益，数值越大运动检测越敏感。取值范围: [0, 31]，默认值为12。值越小，运动主体越模糊，拖尾越明显，背景越模糊；值越大，运动越实，背景越清晰。

    motion_thr

    支持Hi3516CV610的pro模型。

    运动阈值，数值越大判断为运动的区域越小。取值范围: [0, 255]，默认值为128。关闭3DNR时，运动阈值越大，画面噪声越安静，拖尾越明显；值越小则噪声越躁动，拖尾越不明显。

    motion_noise_control

    支持Hi3516CV610的pro模型。

    控制运动和静止融合区域的噪声，数值越大对噪声的抑制越强。取值范围: [0, 255]，默认值为128。

    tf_speed_fine

    支持Hi3516CV610的pro模型。

    精细收敛系数，数值越大收敛越快。数值过大，影响运动后有残影，数值过小，影响噪声大。取值范围: [0, 255]，默认值为85。

    tf_speed_coarse

    支持Hi3516CV610的pro模型。

    粗调收敛系数，数值越大收敛越快。数值过大，影响运动后有残影，数值过小，影响噪声大。取值范围: [0, 255]，默认值为77。

    【注意事项】

    • 仅Hi3516CV610的pro模型支持。
    • load_ref_en = 0时，模型再次切换为pro模型时不会刷新参考帧，如果画面内容发生了变化，可能会导致输出结果异常，例如画面有残影。当aibnr数据流开启且最开始选择了pro模型，内存会重新分配，即使load_ref_en = 0也不会导致画面残影。
    • AIBNR图像效果使能开关从关到开时，load_ref_en = 0时，pro模型不会重新加载参考帧。
    • load_ref_en参数可以动态设置，但是只在pro模型开启时或切换到pro模型时才会生效。

    AIISP被抢占导致性能不足时，如何进行丢帧处理

    【现象】

    AIISP和用户推理任务同时开启，且用户推理任务的优先级比AIISP高时，可能导致AIISP性能不够，进而丢帧。

    【解决方法】

    AIISP和用户推理任务都会占用NPU性能，NPU会根据处理任务的优先级高低进行任务调度和抢占，数值越小优先级越高（AIISP的优先级默认为1，推理任务默认优先级为3）：

    • 如果期望AIISP不丢帧，可以将用户推理的优先级设置低于AIISP的优先级，优先保证AIISP的性能。设置优先级可以参考svp_acl_mdl_load_with_config(详见《应用开发指南》）的使用方法。
    • 如果实际业务需要主动丢帧，可以通过设置VI的帧率控制，做降帧处理，从而达到一个相对均匀的丢帧效果。

    线性AIISP和WDR宽动态模式如何动态切换

    【现象】

    Hi3516CV610上线性AIISP和WDR宽动态模式动态切换失败。

    【解决方法】

    加载ko脚本的时候必须指定模块参数-profile 2，才可以支持线性AIISP和WDR模式动态切换，切换过程中要销毁和重建VI通路，但不用销毁isp，退出线性AIISP的时候需要卸载AIISP模型。

    AIISP和WDR宽动态模式动态切换容易出现内存碎片，为了避免这个问题可以设置AIISP内存独立分区，方法参考小内存单板加载模型时空间不足，如何设置独立分区小节。

    小内存单板加载模型时空间不足，如何设置独立分区

    【现象】

    小内存单板由于出现内存碎片，导致AIISP模型加载失败。

    【解决方法】

    1. 加载ko脚本时，修改脚本或加载指令，例如:

      ./load3519dv500 -a -mmz_start 0x48200000 -mmz_size 1853M:aiisp,0,0xBBF00000,65M;

      其中"mmz_size 1853M:aiisp,0,0xBBF00000,65M"部分根据AIISP实际需要计算：

      AIISP需要65M时, 匿名区域剩余1918 - 65 = 1853M; AIISP分区起始地址为0x48200000+0x73D00000(1853M)=0xBBF00000。

    2. AIISP业务初始化前调用ss_mpi_sys_set_mem_cfg接口设置AIISP使用独立分区：

      ot_mpp_chn mpp_chn = { OT_ID_AIISP, 0, 0 }; /* AIISP只支持dev0, chn0 */

      td_char *mmz_name = "aiisp";

      ss_mpi_sys_set_mem_cfg(&mpp_chn, mmz_name);

    - 模型占用的算力大致可以通过分辨率、帧率线性换算，其他分辨率、帧率可以通过表中性能一列中列出的典型分辨率帧率下占用的算力进行线性换算。
    - aibnr_model_denoise_priority.bin、aibnr_model_denoise_priority_lite.bin、aibnr_model_detail_priority_lite.bin 模型的算力在不同分辨率下的折算方式：
    2688 <= width <= 3840，可以根据典型分辨率2688*1520的算力线性折算；
    width < 2688，不能根据2688*1520典型分辨率的算力折算，需要实测。
    - 模型的类型为A类，表示当前模型经过功能和效果充分验证；模型的类型为B类，表示当前的模型功能经过充分验证，效果验证典型场景，客户仅作参考。
