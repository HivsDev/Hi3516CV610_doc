    CIPHER DRIVER

    • 功能描述

    • 使用流程

    功能描述

    CIPHER DRIVER为安全算法模块，包括两层接口：MPI层、KAPI。

    接口说明：

    • MPI 层

      由用户层应用调用，为 CA/TA 提供安全驱动能力。

    • KAPI 层

      由内核模块调用，为内核模块提供安全驱动能力。

    功能描述：

    • CIPHER DRIVER提供如下算法：

      • AES、SM4、TDES等对称加解密算法；
      • HASH、SM3及HASH-MAC、SM3-MAC摘要算法；
      • PBKDF2 算法；
      • RSA、ECC、SM2等非对称签名验签、密钥协商、加解密算法，大数运算；
      • 随机数算法。

    • CIPHER DRIVER包括3个子模块：SPACC、PKE、TRNG。

    • SPACC

    • PKE

    • TRNG

    SPACC

    SPACC（Security Protocol Accelerator，安全协议加速器）模块实现了对称加解密算法、HASH及HMAC摘要算法。

    • 对称加解密算法

    • 摘要算法

    对称加解密算法

    • AES：支持ECB/CBC/CFB/OFB/CTR/CCM/GCM/CMAC/CBC_MAC共9种工作模式。其中：

      • CFB模式支持的加密数据位宽可为8/128bit，Hi3516CV610、Hi3511CV100支持1bit。
      • ECB/CBC/OFB/CTR/CCM/GCM/CMAC/CBC_MAC模式支持的加密数据位宽可为128bit。
      • CCM/GCM模式下，加解密结束后需获取一次TAG值。
      • ECB、CBC、CBC_MAC模式加密数据长度必须为16字节对齐，CMAC允许最后一块加密数据长度非16字节对齐。
      • 支持AES-128/AES-256/AES-192（128、256、192均指传入的密钥长度，单位为bit）。注：Hi3519DV500不支持AES-192。
      • CCM/GCM模式下，加密数据位宽为无效参数。

    • SM4：支持ECB/CBC/CTR共3种工作模式，Hi3516CV610、Hi3511CV100还支持CFB/OFB模式。支持SM4-128；除CTR模式外，加密数据长度须为16字节对齐。

    • TDES：支持CBC/CFB/ECB/OFB共4种工作模式。支持TDES-128。其中：
      • CFB模式支持的加密数据位宽可为8/64bit。
      • CBC/ECB/OFB模式支持的加密数据位宽可为64bit。
      • ECB/CBC模式加密数据长度必须为8字节对齐。

    cipher驱动支持软件多通道，单个进程最多可以同时申请32个，Hi3516CV610、Hi3511CV100默认配置为8个；支持低功耗模式，默认开启低功耗；支持轮询和wait_event模式，默认开启wait_event模式。

    须知：
    - TDES算法及ECB模式属于非安全算法，不建议使用。
    - Hi3516CV610、Hi3511CV100不支持TDES算法。
    - Hi3519DV500不支持AES-192。

    摘要算法
    • HASH：支持SHA256/SHA384/SHA512/SM3。
    • HMAC：支持HMAC_SHA256/HMAC_SHA384/HMAC_SHA512/HMAC_SM3。
      • HASH和HMAC支持中途传入非block size对齐的数据块；
      • 支持软件多通道，单进程最多可以同时申请32个，Hi3516CV610、Hi3511CV100默认配置为8。

    说明：
    Hi3516CV610、Hi3511CV100不支持SHA384/SHA512、HMAC_SHA384/HMAC_SHA512。
    HMAC走长期通道，计算时会占用一个物理通道；HASH走短期通道，计算时会占用一个软件通道。

    PKE

    PKE（Public Key Encryption，公钥加密），即非对称加解密算法。常用于文件的签名和验签，以及非对称密钥的加解密，主要包括以下算法：

    • RSA

      • 支持 PKCS#1 v1.5和 PKCS#1 v2.1 PSS两种模式的私钥签名和公钥验签。
      • 支持PKCS#1 v1.5 和 PKCS#1 v2.1 OAEP两种模式的公钥加密和私钥解密。
      • 支持密钥位宽2048/3072/4096。

    • ECC

      • 支持 RFC 5639 - Brainpool 256/384/512、NIST FIPS 186 - 4 P 256/384/521 和 RFC 8032 - ED25519（即EDDSA）的私钥签名和公钥验签，Hi3516CV610、Hi3511CV100不支持RFC 8032。
      • 支持密钥位宽256/384/512(521)。

    • SM2

      • 支持SM2公钥加密和私钥解密。
      • 支持SM2私钥签名和公钥验签。

    • 密钥协商

      • 支持RFC 5639 - Brainpool 256/384/512、NIST FIPS 186 - 4 P 256/384/521、RFC 7748 - Curve25519、 RFC 8032 - ED25519（即EDDSA）和SM2的公私钥对生成，及由给定的私钥生成其对应的公钥，Hi3516CV610、Hi3511CV100不支持RFC 7748和RFC 8032。
      • 支持RFC 5639 - Brainpool 256/384/512、NIST FIPS 186 - 4 P 256/384/521、RFC 7748 - Curve25519和SM2的密钥交换（ECDH），Hi3516CV610、Hi3511CV100不支持RFC 7748。

    • 曲线上点的验证

      支持RFC 5639 - Brainpool 256/384/512、NIST FIPS 186 - 4 P 256/384/521和SM2的点是否在曲线上的验证。

    • 大数运算

      • 支持256/384/521/2048/3072/4096位的模加、模减、模乘和模运算。
      • 支持256/384/521的模逆、乘法运算；支持密钥位宽为256位的Curve25519蒙哥马利点乘。
      • 支持密钥位宽为256位的ED25519 ED点乘。
      • 支持密钥位宽为256/384/521位的ED点加（Uranus ES不支持）。
      • 支持密钥位宽为256/384/521位的ECC点乘、点加、倍点运算。
      • 支持2048/3072/4096位的模幂运算。
      • Hi3516CV610、Hi3511CV100不支持大数运算。

    PKE支持低功耗模式，并支持PKE时钟的开启与关闭。当关闭时钟时，PKE模块整个不可用。支持轮询和wait_event模式，默认开启wait_event模式。

    须知：
    - 默认不支持NIST FIPS 186-4 P256/384/521曲线，如需打开需要用户在security_subsys/crypto_features.h中定义宏CONFIG_PKE_SUPPORT_ECC_FIPS_P256R、CONFIG_PKE_SUPPORT_ECC_FIPS_P384R、CONFIG_PKE_SUPPORT_ECC_FIPS_P521R，并重新编译驱动。
    - 默认不支持RSA算法PKCS#1 v1.5填充模式，如需打开需要用户在security_subsys/crypto_features.h中定义宏CONFIG_PKE_RSA_V15_SUPPORT，并重新编译驱动。
    - 默认不支持对称算法ECB模式，如需打开需要用户在security_subsys/crypto_features.h中定义宏CONFIG_SYMC_MODE_ECB_SUPPORT，并重新编译驱动。
    - 默认不支持RSA2048，如需打开需要用户在security_subsys/crypto_features.h中定义宏CONFIG_PKE_RSA_2048_SUPPORT，并重新编译驱动。
    - 默认不支持SHA224，如需打开需要用户在security_subsys/crypto_features.h中定义宏CONFIG_HASH_SHA224_SUPPORT，并重新编译驱动。

    HASH计算

    • 场景说明

    • 工作流程

    • 注意事项

    场景说明

    获取消息摘要。

    工作流程
    1. HASH 模块初始化。调用 ot_mpi_cipher_hash_init接口完成。
    2. 创建一路HASH，配置当前HASH计算类型，并获取HASH句柄。调用ot_mpi_cipher_hash_create 接口完成。
    3. 传入消息数据，对消息进行摘要计算，调用ot_mpi_cipher_hash_update 接口完成。
    4. 获取消息摘要，调用ot_mpi_cipher_hash_finish接口完成。
    注意事项

    支持多段数据连续update，结果与多段数据一次性update结果一致。

    HMAC计算

    • 场景说明

    • 工作流程

    • 注意事项

    场景说明

    计算一块数据的 HMAC值。

    工作流程
    1. HASH 模块初始化。调用 ot_mpi_cipher_hash_init 接口完成。
    2. 创建一路HASH，配置当前HMAC算法及密钥并获取HASH句柄。调用ot_mpi_cipher_hash_create 接口完成。
    3. 传入消息数据，对消息进行摘要计算，调用ot_mpi_cipher_hash_update 接口完成。
    4. 获取消息摘要，调用ot_mpi_cipher_hash_finish接口完成。
    注意事项

    HASH Clone 计算

    • 场景说明

    • 工作流程

    • 注意事项

    场景说明

    计算HASH(Message1 || Message2)，其中Message1的处理由hash_handle1完成，Message2的处理由hash_handle2完成，最终由hash_handle2计算出HASH(Message1 || Message2)的结果。

    工作流程
    1. HASH 模块初始化。调用 ot_mpi_cipher_hash_init 接口完成。
    2. 创建一路HASH，设置当前HASH算法获取hash_handle1。调用ot_mpi_cipher_hash_create 接口完成。
    3. 创建第二路HASH，获取hash_handle2。调用ot_mpi_cipher_hash_create 接口完成。
    4. hash_handle1 传入 Message1进行摘要计算，调用ot_mpi_cipher_hash_update接口完成。
    5. 获取 hash_handle1的计算中间结果，调用ot_mpi_cipher_hash_get接口完成。
    6. 销毁hash_handle1，调用ot_mpi_cipher_hash_destroy接口完成。
    7. 将步骤5获取的中间结果设置到 hash_handle2，调用ot_mpi_cipher_hash_set接口完成。
    8. hash_handle2传入Message2进行摘要计算，调用ot_mpi_cipher_hash_update接口完成。
    9. 使用hash_handle2获取消息摘要，调用ot_mpi_cipher_hash_finish接口完成。
    注意事项
    • 支持多段数据连续update，结果与多段数据一次性update结果一致。
    • HASH Clone计算时，若两个handle的type不一致以第一个handle的配置为准。
    HMAC Clone 计算
    • HMAC在使用硬件算法时，不支持Clone计算
    • HMAC在使用明文key软件算法时，支持Clone计算，流程同HASH Clone
    PBKDF2计算

    调用ot_mpi_cipher_pbkdf2进行PBKDF2计算。

    获取真随机数

    调用ot_mpi_cipher_trng_get_random 获取四个字节的真随机数或调用ot_mpi_cipher_trng_get_multi_random获取任意字节的真随机数。

    对称加解密，工作模式为ECB/CBC/CTR/OFB/CFB/ CFB8
    1. 调用ot_mpi_cipher_symc_init初始化SYMC模块；
    2. 调用ot_mpi_cipher_symc_create创建SYMC句柄；
    3. 调用ot_mpi_cipher_symc_attach绑定KEYSLOT通道，KEYSLOT通道创建可参考KEYSLOT&KLAD相关接口说明；
    4. 调用ot_mpi_cipher_symc_set_config设置算法参数；
    5. 调用ot_mpi_cipher_symc_encrypt进行加密（或调用ot_mpi_cipher_symc_decrypt进行解密）；
    6. 调用ot_mpi_cipher_symc_destroy销毁SYMC句柄；
    7. 调用ot_mpi_cipher_symc_deinit去初始化SYMC模块。

    注意：
    步骤5进行加密后，iv值会更新。如果要使用相同的SYMC句柄进行解密，需要重新进行步骤4设置算法参数。

    对称加解密，工作模式为GCM/CCM
    1. 调用ot_mpi_cipher_symc_init初始化SYMC模块；
    2. 调用ot_mpi_cipher_symc_create创建SYMC句柄；
    3. 调用ot_mpi_cipher_symc_attach绑定KEYSLOT通道，KEYSLOT通道创建可参考KEYSLOT&KLAD相关接口说明；
    4. 调用ot_mpi_cipher_symc_set_config设置算法参数；
    5. 调用ot_mpi_cipher_symc_encrypt进行加密（或调用ot_mpi_cipher_symc_decrypt进行解密）；
    6. 调用ot_mpi_cipher_symc_get_tag获得tag值；
    7. 调用ot_mpi_cipher_symc_destroy销毁SYMC句柄；
    8. 调用ot_mpi_cipher_symc_deinit去初始化SYMC模块。
    SYMC MAC
    1. 调用ot_mpi_cipher_symc_init初始化SYMC模块；
    2. 调用ot_mpi_cipher_mac_start 创建句柄；
    3. 调用ot_mpi_cipher_mac_update传入数据（可调用一次或多次）；
    4. 调用ot_mpi_cipher_mac_finish获取MAC值，并销毁句柄；
    5. 调用ot_mpi_cipher_symc_deinit去初始化SYMC模块。

    • 场景说明

    场景说明

    2. 创建KEYSLOT句柄。调用ot_mpi_keyslot_create接口完成。
    3. 创建KLAD句柄。调用ot_mpi_klad_create 接口完成。
    4. 绑定KLAD和KEYSLOT句柄，调用ot_mpi_klad_attach 接口完成。
    5. 设置KLAD属性，调用ot_mpi_klad_set_attr接口完成。
    6. 设置明文KEY，调用ot_mpi_klad_set_clear_key接口完成。
    7. 解绑定KLAD和KEYSLOT句柄，调用ot_mpi_klad_detach接口完成。
    8. 销毁KLAD句柄，调用ot_mpi_klad_destroy接口完成。
    9. 去初始化KLAD设备，调用接口ot_mpi_km_deinit接口完成。
    注意事项

    KEYSLOT句柄在配置KLAD的过程中必须已创建。

    ROOTKEY传递

    • 场景说明

    • 工作流程

    • 注意事项

    场景说明

    当安全方案要求高的场景下采用，ROOTKEY经密钥解混淆、密钥派生后产生，经多级KLAD传递后得到一个真正的工作密钥。工作密钥存储在硬件中，用户不可读取。KLAD将工作密钥传递给一个KEYSLOT。加解密时，加解密引擎取对应KEYSLOT中的KEY用于加解密。

    工作流程
    1. KLAD 设备初始化。调用 ot_mpi_km_init 接口完成。
    2. 创建KEYSLOT句柄。调用ot_mpi_keyslot_create接口完成。
    3. 创建KLAD句柄。调用ot_mpi_klad_create 接口完成。
    4. 绑定KLAD和KEYSLOT句柄，调用ot_mpi_klad_attach 接口完成。
    5. 设置KLAD属性，调用ot_mpi_klad_set_attr接口完成。
    6. Hi3516CV610、Hi3511CV100设置盐值，调用ot_mpi_klad_set_effective_key接口完成。Hi3519DV500设置一级KEY，调用ot_mpi_klad_set_session_key接口完成；设置二级KEY，调用ot_mpi_klad_set_content_key接口完成。
    7. 解绑定KLAD和KEYSLOT句柄，调用ot_mpi_klad_detach接口完成。
    8. 销毁KLAD句柄，调用ot_mpi_klad_destroy接口完成。
    9. 去初始化KLAD设备，调用接口ot_mpi_km_deinit接口完成。
    注意事项

    KEYSLOT句柄在配置KLAD的过程中必须已创建。

    • session_key为一级密钥。
    • content_key为二级密钥。

    须知：
    - Hi3516CV610、Hi3511CV100不支持二级KLAD派生，即不支持session_key和content_key。只支持使用effective_key，调用ot_mpi_klad_set_effective_key接口完成。
    - Hi3516CV610、Hi3511CV100 OTP密钥区域对应派生密钥类型：
    obfu_mrk1对应密钥CRYPTO_KDF_HARD_KEY_TYPE_ERK_TEE、CRYPTO_KDF_HARD_KEY_TYPE_ERK_REE
    oem_rootkey1对应密钥CRYPTO_KDF_HARD_KEY_TYPE_ERK1_REE
    oem_rootkey2对应密钥CRYPTO_KDF_HARD_KEY_TYPE_ERK2_REE

    td_u16 e_len;      /* *< length of public exponent */

    td_u16 q_len;      /* *< length of 2nd prime factor,should be half of u16NLen */
    td_u16 dp_len;     /* *< length of D % (P - 1),should be half of u16NLen */

    安全驱动

    • Cipher驱动实现了标准的对称加密AES/TDES/SM4算法，非对称RSA、ECDSA/SM2/ED25519算法，摘要算法SHA/SM3/HMAC_SHA/SM3，密钥协商算法ECDH，密钥派生算法PBKDF2，没有使用任何私有算法。

    • 对称算法使用建议：

      • TDES为非安全算法，不建议使用。
      • AES/SM4算法ECB模式为非安全算法，不建议使用。
      • 对称算法的密钥的长度越长，安全等级越高，建议用户使用AES 128bits及以上的密钥。

    • 非对称算法使用建议：

      • RSA算法建议使用密钥长度3072bits及以上的密钥。
      • RSA签名算法padding方式建议使用PSS padding方式。
      • RSA加解密算法padding方式建议使用OAEP padding方式。
      • ECDSA算法建议使用密钥长度256bits及以上的密钥。
      • ECDSA算法曲线不建议使用NIST P256/384/521曲线。

    • 摘要算法使用建议：

      SHA/HMAC_SHA算法建议使用SHA256/HMAC_SHA256及以上的算法。

    • 密钥协商算法使用建议：

      ECDH算法建议使用密钥长度256bits及以上的密钥。

    • 密钥派生算法使用建议：

      • 迭代次数和安全性成正比例，也与计算时间成正比，迭代次数越大，意味着计算密钥花费时间越长，同时抗暴力破解能力越强。对于性能不敏感或高安全性要求场景推荐迭代次数至少需要10000000次，其他场景迭代次数默认推荐至少10000次；对于性能有特殊要求的产品最低可以迭代1000次（NIST SP 800 -132）。
      • 哈希函数推荐选择SHA256或更安全的哈希算法。
      • 盐值至少16字节，应使用安全的随机数。
      • 用于口令单向哈希时，其输出长度应该不小于256bit。

    JTAG接口

    恶意者可通过JTAG接口，篡改系统和配置，恶意破坏系统。

    建议用户采用以下措施：

    • 产品出厂时，将JTAG接口从物理上删除。
    • 芯片提供JTAG disable功能，软件通过写OTP，可从芯片层面直接永久关闭JTAG。
