        Hi3516CV610 FAQ

        本文针对使用 Hi3516CV610 过程中可能遇到的常见疑问，提供解答与规避方案。

        使用建议

        1. 首次使用： 建议先阅读"系统稳定性"和"性能对比"两个章节，了解用版本的基本特征
        2. 遇到问题： 先根据现象在对应模块FAQ中查找，多数问题有明确的规避方案
        3. 性能规划： 业务设计阶段参考FAQ中的性能约束条件，避免超限使用
        4. 持续更新： 本FAQ随版本迭代持续更新，建议关注最新版本说明

        1. 系统和功能

        Q1.1 单板无响应，或sdk_server进程异常退出（OOM），如何处理？

        现象：

        部分业务负载较重的情况下，可能出现如下现象，业务中断或单板无响应

        1、业务运行过程中出现频繁的如下异常打印，业务中断

        [osal_uds_send_recv_multi:222]:send to 14 err:0xffffffff in thread(306267672)!
[osal_uds_send_recv_multi:222]:send to 14 err:0xffffffff in thread(306267672)!

        2、通sdk_server进程异常退出、被os kill等，通过 ps 命令无法查询到 sdk_server 进程

        [SDK Server] initialized successfully, entering main loop...
Killed

        3、串口打印

        [ot_irq: ,line:848] irq(62) VICAP_0_0 dropping old int!

        业务场景可能包含：

        • AIISP aibnr场景下aibnr切换为WDR
        • VPSS全在线卷绕（帧中断模式EARLY_END）
        • VPSS全在线帧中断下动态创建销毁组（帧中断模式EARLY_END）
        • 在线WDR+ VPSS-VENC卷绕

        原因： os内存紧张，导致sdk_server无法分配到足够的内存，或频繁触发os的内存回收，导致系统卡顿/卡死、或sdk_server因为OOM被os Kill。

        解决方案：

        • 在当前的基础上，将OS MEM增大至少2M（默认os分配是32M），具体调整方式见文档《内存布局调整指南》"内存布局修改示例"章节
        • 重启单板

        如仍有问题，请尝试重新运行业务后，通过cat /proc/umap/* > proc_log.txt和cat /dev/mpplog抓取日志

        Q1.2 cat /dev/logmpp查看无任何日志输出？

        现象： cat /dev/logmpp 日志无输出。

        原因：

        1、默认日志等级是 ERROR（严重）以上才打印，当前没有错误日志产生

        2、没有打开logmpp功能

        解决方案：

        1、打开logmpp功能开，步骤如下

        • 加载ko时传递参数：insmod ot_base.ko logmpp_show=1

        • 修改samples/mpp/common/sdk_init/sdk_init.c中的base_init函数，具体修改内容如下

        static td_s32 base_init(td_void)
{
    td_bool logmpp_show = TD_TRUE; /* 修改这里, 改为TD_TRUE */
    return ot_base_mod_init(logmpp_show);
}
        • 进入samples/mpp/sdk_server执行如下命令重编sdk_server
        make clean -j;make -j
        • 重新运行sdk_server即可

        2、如何修改各个模块的logmpp级别

        • 查看模块。数字表示日志级别，越小表示日志级别越高。例如3表示ERROR级别，6表示INFO级别。具体可以参考头文件"ot_debug.h"中的定义。
        # cat /proc/umap/logmpp_user
----------------------------------------log buffer state----------------------------------------------------------------
max_len(KB)  read_pos write_pos butt_pos
         64         0         0    65536

----------------------------------------current log level---------------------------------------------------------------
vb      :  3
sys     :  3
region  :  3
……
        • 修改具体模块的logmpp打印级别

        echo "模块=级别" > /proc/umap/logmpp_user，以vi模块为例

        echo "vi=6"  > /proc/umap/logmpp_user

        表示将vi模块日志级别为0-6的都打印到/dev/logmpp中。

        也可以修改所有模块的日志级别，命令为：

        echo "all=6"  > /proc/umap/logmpp_user

        表示将所有模块日志级别为0-6的都打印到/dev/logmpp中。

        日志打印级别的修改，在单板重启或者sdk_server重启之后会恢复到默认级别3。

        Q1.3 sdk_server的CPU占用过高（超过20%），如何处理？

        现象： 业务负载较重的场景下，sdk_server占用率可能持续较高。

        例如 单目4K20fps线性，VI开启3DNR，VPSS组打多个cover，送给智能分析后，出3路编码码流并存储码流。

        原因： 此为已知问题，当前性能需要优化

        解决方案：当前版本需合理规划业务负载，关闭或裁剪不需要的功能，避免长时间满负荷运行。建议控制整体CPU占用不超过80%。后续版本会持续优化。

        Q1.4 如何打开WDR？

        现象：无法使用WDR功能。

        原因： 默认WDR功能未打开。

        解决方案： 按照如下步骤打开WDR功能

        • 修改profile的值。sample/mpp/common/sdk_init/sdk_init.c中，sys_profile默认为0，需要修改sys_profile的值为1。
        static td_s32 sys_init(td_void)
{
    td_u32 sys_profile = 0; /* 修改这里, 改为1 */
    return ot_sys_mod_init(sys_profile);
}
        • 重编sdk_server。进入samples/mpp/sdk_server执行make clean -j;make -j命令重编sdk_server。

        编译后使用新的sdk_server重新运行即可。

        2. 性能

        Q2.1 CPU/NPU/DDR等使用率较高，SDK的接口调用耗时增加，这是正常的吗？

        现象：部分场景下，CPU/NPU/DDR占用较高、帧率可能不达标。涉及场景包括：

        • 单目4M30fps 线性/ 2to1WDR
        • 单目4K20fps 线性（录像机场景）
        • 单目4M12fps AI-ISP（黑光）智能IPC

        原因： 当前架构采用多进程通信提供媒体功能（sdk_server进程），SDK的接口调用通过IPC发送给sdk_server，存在固有的用户态/内核态切换和IPC通信开销（跟交互的数据有关，0.2ms-1ms之间），导致部分性能指标变高。

        解决方案：

        1. 当前多进程通信框架导致，为已知现象，持续优化中
        2. 当前版本需合理规划业务负载，关闭或裁剪不需要的功能

        Q2.2 VI/VPSS通路叠加场景（旋转/OSD/卷绕/3DNR）性能不足，怎么办？

        现象： VI在线VPSS离线模式下，叠加旋转/OSD/卷绕/3DNR功能时，预期最大性能跑2560x1440@25，实际跑不到。

        原因： VI-VPSS通路叠加场景性能受限。

        解决方案：

        1. 增加VB缓存块数量（多分配2-3块），保证轮转模块有足够的VB轮转，增加后可以跑到2560x1440@18以上
        2. 降低帧率预期，参照实际测试数据规划业务
        3. 减少同时叠加的功能数量（如不同时开启旋转+卷绕+3DNR）

        Q2.3 多线程/多路场景下接口调用超时或帧率下降，如何处理？

        现象：
        - VPSS用户多线程获取多通道帧时，每个线程获取帧的效率降低，且有概率超时
        - IVE多算子多线程同时执行时，出现任务队列满等待超时（errcode:0xa01d8017）
        - IVSMD同时跑多路处理时，DMA拷贝数据时出现mpi_ive_query查询超时，性能下降

        原因： 多线程/多路并发场景下性能受限。

        解决方案：
        1. VPSS多线程： 避免多线程同时获取多个通道帧，改为单线程轮询或减少并发通道数
        2. IVE多算子： 控制同时执行的算子数量，避免一次性批量处理多帧大分辨率数据
        3. IVSMD多路： 开启aidetect运动检测或者ive md运动检测时，不要在数据通路叠加ive dma拷贝等操作

        3. 视频输入（VI）

        Q3.1 3DNR场景下起pipe1输出异常（只有1帧），如何规避？

        现象： 3DNR去噪自动模式下，起pipe0时业务正常（30帧），但起pipe1时VI输出只有1帧。

        原因： 3DNR场景下的pipe1异常。

        规避方案： 使用3DNR功能时，仅使用pipe0通路，避免使用pipe1。后续版本会优化解决该问题。

        Q3.2 虚拟pipe送raw12格式图像出现花屏？

        现象： 虚拟pipe送raw12格式的图源，输出图像花屏

        原因： 仅虚拟pipe的raw12格式受限。

        规避方案： 虚拟pipe场景下避免使用raw12格式，改用raw8/raw10/raw14/raw16等其他格式。后续版本会优化解决该问题。

        4. 视频处理（VPSS）

        Q4.1 VPSS多路低延时+卷绕+普通叠加后编码通道过多，导致报错和卡死？

        现象： VPSS开启6路低延时+6路卷绕+6路普通，对接16路编码，业务运行后报错或卡死

        原因： 多路极限性能受限，资源不足

        规避方案：

        1. 该场景为极限性能场景，不建议在实际业务中使用，需要减少低延时/卷绕通道的组合数量

        Q4.2 VPSS通道VB缓存块不足时降帧率？

        现象： 实际运行过程中，每个通道在只有2块对应大小的VB时会降帧率。

        解决方案： 增加每个通道的VB缓存块数量，建议至少配置3-4块VB。

        5. 编码（VENC）

        Q5.1 VENC开启fixqp mjpeg编码出现内存分配不足打印？

        现象： VENC开启fixqp mjpeg协议编码过程中出现内存分配失败打印，功能运行正常，可能出现如下打印

        sdk_server: page allocation failure: order:4, mode:0x40cc0(GFP_KERNEL|__GFP_COMP), nodemask=(null)
CPU: 1 PID: 915 Comm: sdk_server Tainted: P           O      5.10.221 #1

        原因： 特定场景OS内存不足导致

        解决方案：

        1、增加OS内存分配（增大OS MEM），可消减因内存不足导致的风险。

        2、降低业务负载，裁剪不必要的功能

        Q5.2 VENC同时开启5个通道编码，第5通道select异常？

        现象： VENC同时开启5个通道进行编码，第5个通道的select会默认通过，但查询编码状态实际不存在码流包。

        原因： 5通道编码场景，4通道无此问题。

        规避方案： 避免同时开启5个及以上VENC编码通道，当前建议最多使用4个通道。后续版本持续优化。

        6. ISP/AIISP/AIBNR

        Q6.1 AIBNR切换为WDR时异常，sdk_server异常退出？

        现象： AIBNR切换为WDR时，串口和日志出现异常打印，切换失败，sdk_server进程异常退出。

        解决方案： 参见 Q1.1

        Q6.6 WDR自动降帧场景下，镜头遮挡后放开时画面卡住？

        现象： WDR在线业务中（VI在线，VPSS离线），AE自动模式下（短帧优先和长帧优先都存在），自动降帧模式，镜头对着工频闪灯泡，用手遮住镜头后放开，点播画面卡住，VI和VPSS通道帧率为0。

        原因： WDR自动降帧功能异常。

        规避方案：

        1、关掉BNR

        2、避免在WDR自动降帧模式下进行极端的光照突变操作（如遮挡镜头后突然放开）

        后续版本优化解决。

        7. 智能算子（SVP/NPU）

        Q7.1 IVE多算子多线程执行出现任务队列满？

        现象： IVE多算子多线程同时执行时，出现errcode:0xa01d8017，提示任务队列满等待超时。

        原因： 多算子多线程性能不足。

        规避方案：
        1. 控制同时执行的IVE算子数量
        2. 避免一次性批量处理多帧大分辨率数据
        3. 降低处理帧率

        Q7.2 ACL多模型多线程运行时单板中断异常？

        现象： SVP ACL的aicpu用例，跑多模型多线程时单板中断上报异常。

        原因： 两路及以上的CPU模型算子在多个和线程同时运行时出现，原因为中断性能处理不足导致

        规避方案：

        1、建议使用NPU模型

        2、运行CPU模型时，建议单路执行

        Q7.3 SVP NPU Sample运行需要增大OS内存？

        现象： 使用默认32M OS内存运行sample_svp_npu_main时，日志一直打印vi_pipe相关报错。

        解决方案： 增大OS内存分配，建议从默认32M调整到48M或更高。

        8. AI检测（AIComponent）

        Q8.1 两路aidetect都开启运动检测，其中一路退出后另一路推理报错？

        现象： 两路aidetect都开启运动检测，其中一路退出，另一路继续推理会报错。

        原因： 两路aidetect场景，其中1路退出后导致异常。

        规避方案： 多路aidetect场景下，避免中途单独退出某一路。如需停止，建议同时停止所有aidetect通路。

        9. 区域叠加（REGION）

        Q9.1 VGS的RGN Luma接口当前不可用？

        现象： VGS的RGN Luma接口当前不可用。

        原因： 此接口暂不支持

        说明： 涉及Luma接口获取的相关业务等待后续版本支持。

        10. PQTools调参工具

        Q10.1 PQT调节AE参数时突然无法调节（其他参数调节正常）？

        现象： WDR在线业务中（VI在线，VPSS离线），PQTools设置参数过程中，无法调节AE参数（其他参数能正常调节），PQT业务端口和sdk_server端口报错

        原因： 内存等性能不足，低概率问题

        规避方案：

        1、将OS MEM调大到48M或更高

        2、重启PQTools连接或重启sdk_server

        Q10.2 PQT在线线性业务（vi在线，vpss离线）运行一段时间后，重启PQT业务失败？

        现象： 在运行在线线性业务（vi在线，vpss离线），启动AE的3A和点播长时间运行后，重新启动业务，业务无法正常起来

        原因： 内存等性能不足，低概率问题

        规避方案：

        1、重启PQTools连接或重启sdk_server

        2、将OS MEM调大到48M或更高

        3、AE 3A和点播不同时使用

        Q10.3 默认32M内存下单板运行PQT工具异常？

        现象： 默认32M内存配置下，PQT工具有多个场景运行异常

        工具使用的业务场景可能包括：

        • 启wdr业务、3A统计抓图功能，无法获取统计信息
        • 部分aibnr业务：hy006_3814_0011_4M15_large_mem_aiisp_send_raw.ini、hy006_3814_0011_4M5_large_mem_aiisp_send_raw.ini（128M DDR不支持）
        • FPN标定（128M DDR不支持）
        • 灌raw/yuv后，进行点播、3A抓图、抓jpeg（128M DDR不支持）
        • 板端自动灌YUV抓码流

        原因： 默认32M的OS内存不足，或128M DDR单板上无法运行

        解决方案：

        1、 增大OS内存分配，建议从默认32M调整到更大值。

        2、需要128M以上DDR的场景，当前不支持

        11. 系统公共模块（SYS/VB）

        Q11.1 日志等级设置接口返回错误但实际生效？

        现象：
        - ss_mpi_log_set_level_cfg设置日志等级成功，但接口返回错误
        - ss_mpi_log_get_level_cfg接口调用返回错误
        - ss_mpi_log_set_wait_flag接口功能配置生效，但接口返回错误

        原因：接口返回处理异常

        解决方案：

        1、 暂时忽略接口返回值，以实际效果为准，后续版本修复

        2、参考 Q1.2 使用cat方式查看和获取日志等级
