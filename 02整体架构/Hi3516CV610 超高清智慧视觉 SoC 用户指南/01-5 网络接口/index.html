        概述

        以太网模块提供了1个Ethernet MAC，实现网络接口数据的接收和发送，可以工作在10Mbit/s或100Mbit/s模式下，支持全双工或者半双工工作模式，提供MII，提供可配置的8组DMAC地址过滤表，可以对网口的输入帧进行选择性过滤接收，同时实现了对CPU端口流量限制功能，保护CPU不被大流量攻击。

        功能描述

        Ethernet模块有如下功能特点：

        • 提供1个Ethernet MAC。
        • 支持10Mbit/s或100Mbit/s速率。
        • 可工作在全双工或半双工模式。
        • 对内置PHY提供MII接口。
        • 支持半双工模式下的碰撞回退重传和late collision。
        • 支持全双工模式下的流控帧的发送。
        • 支持帧长有效性检测，丢弃超长帧和超短帧。
        • 支持对输入帧进行CRC校验，可丢弃校验错的帧。
        • 支持对输出帧添加CRC校验。
        • 支持短帧填充功能。
        • 提供自适应功能。
        • 提供MDIO接口，MDIO接口时钟频率可调整。
        • 提供64个接收和发送共用的帧管理队列。
        • 提供流量限制功能，防止针对CPU的流量攻击。
        • 支持对接收和发送帧进行统计计数。
        • 支持8个可配置的DMAC地址过滤表。
        • 对广播帧、组播帧和单播帧支持可配置是否转发或者丢弃。
        • 支持SG(Scatter Gather) 分散聚合功能。
        • 接收、发送方向都支持COE（Checksum Offload Engine）校验和卸载引擎功能。
        • 支持TSO（TCP Segmentation Offload）TCP分段卸载功能。
        • 支持UFO（UDP Fragmentation Offload）UDP分段卸载功能。

        收帧过程

        初始化时软件需要完成以下操作：

        • 软件需要申请与配置的输入队列深度个数相同的缓冲区，每个缓冲区的大小为2KB，然后将缓冲区首地址依次写入到帧输入队列中，写入的次数应刚好等于配置的输入队列的深度。
        • 软件需要保证配置的缓冲区在收帧时不能释放。如果配置的首地址为非word对齐地址时，需确保该地址对应的字节地址为可写地址。

        当CPU获知有1帧数据需要接收时，执行以下步骤：

        1. 读取寄存器UD_GLB_IQFRM_DES中的帧描述子（包含输入帧的起始地址和帧长度信息）。
        2. 处理数据，并将GLB_IRQ_RAW[iraw_rx_up]写1清0（表示CPU收帧结束）。

        软件收完1帧数据后需要重新申请一个2KB的缓冲区，并将首地址重新写入到当前输入队列帧描述子中。否则，实际可以使用的输入队列的深度不等于CPU配置的数值，而等于CPU实际分配的缓冲区个数。

        发帧过程

        CPU有帧待发送时，判断当前队列是否有空间发送。如果有空间发送，则分别写该帧Buffer的首地址和帧长到输出队列帧描述子中。CPU先写入首地址，然后写入发送帧的帧长。写发送帧的帧长触发硬件将该输出帧的首地址和帧长信息写入到输出队列中等待发送。因此，软件应该控制不能任意写帧长寄存器，每写该寄存器一次会导致发送一个数据包。

        CPU发帧可以采用中断方式或查询方式。

        1. 中断方式发帧

          CPU使能Ethernet发包队列由不空到空中断（int_freeeq_up），同时设置允许该中断通知CPU。此时如果Ethernet输出队列由不空到空，说明Ethernet可以发送帧，硬件产生中断通知CPU，表示CPU可以发帧。

          如果软件需要发送帧，但是当前输出队列已满，则软件可以使能该中断。当输出队列为空后，产生中断，通知软件发送等待的帧。软件可以使用该中断一次发送一组帧，同时在该中断有效时释放上次发送的一组帧的缓冲区。

        2. 查询方式发帧

          软件查询自己内部的发帧计数，如果计数小于配置的输出队列长度，则可以直接将待发送的帧通知Ethernet，同时建立对应的发帧索引表，索引表项内容为写入到Ethernet输出队列的输出帧首地址。当Ethernet发送完1帧后，通过输出队列的地址通知CPU释放对应的发送缓冲区，CPU通过该输出队列的地址查找到对应的发送缓冲区并释放。

        中断管理

        中断状态寄存器

        指示产生的中断类型，具体内容请参见“全局控制寄存器”中的“GLB_IRQ_STAT”。

        中断使能寄存器

        控制是否产生相应的中断，具体内容请参见“全局控制寄存器”中的“GLB_IRQ_ENA”。如果使能某中断，其中断状态会写入到相应的中断状态寄存器中。

        原始中断状态寄存器

        可以读取某种类型的原始中断传送给CPU，具体内容请参见“全局控制寄存器”中的“GLB_IRQ_RAW”。在需要清除中断状态时，必须先清除该中断的原始中断，原始中断清除后，中断状态会自动清除。

        流量控制

        对于软件接收的帧，当单位时间间隔内接收到的帧超过软件配置上限时，则将后续接收的帧按配置进行选择性丢弃。软件可配置超过流量限制后丢弃广播帧、组播帧或者单播帧（通过UD_GLB_FC_DROPCTRL配置）。流量限制阈值通过UD_GLB_FC_RXLIMIT设置。

        软件可配置寄存器UD_GLB_FC_TIMECTRL来设置流量限制的时间间隔。使用1个10bit时间间隔寄存器，最大可以是1023个时间粒度。时间间隔粒度采用17bit计数器，对主时钟进行计数，默认值是100000，对于100MHz主时钟时间粒度为1ms。软件可配置（20bit寄存器）流量限制上限值的大小，若配置为0表示不进行流量限制全部接收。

        概述

        FEPHY（Fast Ethernet PHY）IP是一个支持单口10BASE-T/10BASE-Te/100BASE-TX以太网物理层的IP。

        功能特点

        FEPHY实现了10BASE-T/10BASE-Te/100BASE-TX以太网物理层，在电缆一端，该模块的MDI接口通过变压器以及RJ45接口直接与双绞线相连；在MAC端，通过该模块的MII接口与MAC层相接。

        • 兼容IEEE的10BASE-T/100BASE-TX；
        • 电缆状态的诊断功能；
        • 支持MDIO和MII接口；
        • 支持IEEE802.3u的自协商和并行检测功能；
        • 支持电缆线对自动交叉倒换和极性调整；
        • 支持802.3az (Energy Efficient Ethernet)；
        • 支持10M/100Mbps下眼图测试序列直接发送，通过配置寄存器实现，测试眼图无需依赖tesgine；
        • 电压型输出，不需上下拉电阻，变压器抽头只需电容接地。

        • 在电缆一端，MDI接口通过一个变压器以及RJ45接口直接与双绞线相连；
        • 在MAC端，FEPHY通过MII接口与MAC层相接。

        手动配置

        FEPHY核可以通过多种方式配置。所有的配置都可以通过MDIO接口，读写寄存器进行管理。要使用手动配置模式，必须先屏蔽自协商功能，通过以下方法实现：

        1. 配置0x0到寄存器BMCR（地址0x00）的bit 12。
        2. 配置寄存器BMCR（地址0x00）的SPEED[1:0]域用于确定速度。
        3. 配置寄存器BMCR（地址0x00）的Duplex[1:0]域用于确定双工模式。

        自协商

        10/100Mbps以太网PHY对自协商的支持是可选的，当对端的设备不支持自协商时可以通过并行检测（parallel detecting）的方式来确定连接的模式。

        速度、双工模式选择与优先级定义

        自协商功能提供了一种让对接的双方可以交换配置信息的机制。这个机制是通过交换Fast Link Pulse（FLP）来实现的。自协商的过程中，连接双方都支持的最高性能的协议会被优先选中。

        自协商选择过程中各种模式的优先级如下：

        1. 100BASE-TX Full Duplex (最高优先级)
        2. 100BASE-TX Half Duplex
        3. 10BASE-T Full Duplex
        4. 10BASE-T Half Duplex (最低优先级)

        并行检测

        当对端的设备不支持自协商，则自协商功能模块利用这些收到的信息确定将使用的连接协议（10BASE-T和100BASE-X会发送不同的信号表示不同的链路状态）。如果FEPHY是以并行检测来完成自协商过程，可通过以下寄存器来确认当前状态：

        • 寄存器ANLPARD的bit5和bit7可以指示对端的连接模式。
        • 寄存器ANLPARD的bit[4:0]若为0x00001指示一个成功的并行检测和一个符合IEEE802.3的对接设备。
        • 寄存器ANER（地址0x06） bit0若为0表示协商是通过并行检测完成的。
        • 寄存器ANER（地址0x06） bit4若为1表示并行检测错误，未正常建立链接。

        重启自协商

        当自协商成功建立链接后又断链，则自协商会重启再次配置连接。

        • 若此时自协商使能，可以通过写0x1至寄存器BMCR（地址0x00）bit9来重新开始自协商。
        • 若此时自协商不使能，可以通过写0x1到寄存器BMCR（地址0x00）bit12来重新开启自协商功能。

        AUTO—MDIX

        FEPHY核可以检测到是通过“交叉线”还是“直连线”与对端PHY连接。它可以自动调整通道A和B用来初始化10/100的连接。自动MDIX接口调整是在自协商信息交互之前完成的。可通过以下寄存器来确认当前状态：

        • 寄存器LINK_AN（地址0x11）bit10表示MDIX状态。
        • 寄存器AUX_CTL（地址0x12）bit15表示AUTO-MDIX使能
        • 当AUTO-MDIX使能被关闭，此时需要通过配置AUX_CTL（地址0x12）bit14来决定MDI或者MDIX模式。

        极性修正

        FEPHY核可以自动检测和修正接收双绞线的极性（＋/－）。

        寄存器LINK_AN（地址0x11）bit[15:12]可表示当前接收双绞线的极性状态。

        PHY地址

        FEPHY核拥有唯一的5bits位宽PHY地址，PHY地址的修改支持两种模式：

        • 上电初始化修改

          PHY上电或者复位前通过配置寄存器PERI_FEPHY[4:0]，使PHY在初始化时进行采样。

        • 在线修改

          上电后可以通过修改寄存器PHY ADDRESS（地址0x1f）bit[4:0]来重新定义PHY地址。

        MII Isolate

        在Isolate模式下，FEPHY核自协商功能将被关闭，但仍然可以通过MDIO接口控制。相关配置方法如下：

        • 配置0x1至寄存器BMCR（地址0x00）bit10可进入Isolate模式。
        • 寄存器BMCR（地址0x00）中的SPEED[1:0]控制当前的模式。

        Power Down模式

        当FEPHY进入Power Down模式后，内部电路除了管理接口（MDC/MDIO）将全部下电。这种模式下FEPHY核的功耗最小。配置方法如下：

        配置0x1至寄存器BMCR（地址0x00）bit11可进入Power Down模式。

        拓展寄存器访问

        专用拓展寄存器访问模式

        FEPHY核包含了除IEEE定义的32个基本寄存器外的拓展寄存器。这些拓展寄存器放在拓展寄存器空间，需要通过基本寄存器的“拓展寻址”方式访问。访问流程如下：

        1. 配置PHY进入Power Down模式，确保内部动作不会影响对寄存器的操作。
        2. 将需要访问的寄存器地址写入寄存器EXPMA（地址0x1e），若为写操作则跳至步骤 3，若为读操作则跳至步骤 4。
        3. 将需要写入的数据写入寄存器EXPMD（地址0x1d）。
        4. 读取寄存器EXPMD（地址0x1d）。
        5. 配置PHY脱离Power Down模式，访问结束。

        Clause22拓展寄存器访问模式

        Clause22标准又定义一种扩展模式，由寄存器MACR（地址0xD）和寄存器MAADR（地址0xE）来实现。

        访问流程如下：

        1. 配置寄存器MACR Function域为0x00选择address，将期望操作的MMD地址写入DEVAD域。
        2. 将期望操作的MMD寄存器的地址写入寄存器MAADR。
        3. 配置寄存器MACR Function域为0x00选择Data, no post increment，将期望操作的MMD地址写入DEVAD域。若为写操作则跳至步骤 4，若为读操作则跳至步骤 5。
        4. 将期望的数据写入寄存器MAADR，操作结束。
        5. 读取寄存器MAADR获取数据，操作结束。
