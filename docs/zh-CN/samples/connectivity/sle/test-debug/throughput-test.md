# SLE 吞吐量测试

> 本页只说明测试方法和结果分析。数据通道、流控和发送循环请参考 [高吞吐传输](../data-comm/high-throughput.md)。

## 测试目标

- 测量应用有效吞吐量，而不是物理层标称速率。
- 在相同环境下比较 PHY (Physical Layer) 、MCS (Modulation and Coding Scheme) 、连接间隔和数据长度。
- 记录丢包、重传和稳定性，避免只关注峰值速率。

## 指标定义

有效吞吐量按接收端实际收到的业务数据计算：

```text
有效吞吐量(bit/s) = 接收有效字节数 × 8 ÷ 测试时长(s)
丢包率 = (发送包数 - 接收包数) ÷ 发送包数 × 100%
```

包序号、时间戳和协议头不应计入业务有效载荷。测试报告必须同时记录平均值、峰值、丢包率和持续运行时间。

## 测试前提

1. 使用同一对开发板和相同固件版本。
2. 固定板间距离、天线方向和电磁环境。
3. 关闭无关日志，避免串口输出限制发送速度。
4. 确认双方 PHY、MCS、MTU (Maximum Transmission Unit) 和连接参数实际生效。
5. 预热链路后再开始计时。

## 单变量测试

每轮只改变一个参数：

| 轮次 | PHY/MCS | 载荷长度 | 连接参数 | 目的 |
| --- | --- | --- | --- | --- |
| 基线 | 默认 | 固定 | 固定 | 建立参考值 |
| PHY/MCS | 逐档变化 | 固定 | 固定 | 比较物理层配置 |
| 载荷 | 固定 | 逐档变化 | 固定 | 查找协议开销拐点 |
| 连接参数 | 固定 | 固定 | 逐档变化 | 比较时延和吞吐 |

不要同时改变多个变量，否则无法判断性能变化来源。

## 操作步骤

1. 按 [高吞吐传输](../data-comm/high-throughput.md) 构建并烧录 Server、Client。
2. 确认连接、MTU、PHY 和 MCS 配置成功。
3. 清零发送包数、接收包数和有效字节计数。
4. 在固定时间窗口内运行测试。
5. 由接收端输出最终统计结果。
6. 每组参数至少重复三次，记录平均值和波动范围。

## 问题定位

| 现象 | 优先检查 |
| --- | --- |
| 吞吐明显低于预期 | PHY/MCS 是否生效、发送端是否等待流控、日志是否过多 |
| 峰值高但波动大 | 信道干扰、任务调度、缓冲区深度和统计窗口 |
| 丢包持续增加 | 接收处理是否及时、序号统计是否正确、流控是否被忽略 |
| 距离增加后突然断链 | 当前 MCS 是否过高、重传是否耗尽、天线方向是否变化 |

## 报告要求

测试结论必须附带固件版本、target、参数组合、板间环境和原始日志。不能用单次峰值代替稳定吞吐，也不能把物理层速率直接写成应用吞吐量。
