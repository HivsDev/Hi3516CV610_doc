    代码流程

    1. 启动数据流通路，从前往后分别启动各媒体模块（VI、VPSS、VENC......）。
    2. 初始化aibnr模块，详细使用参考接口ss_mpi_aibnr_init。

    fast_ae

    本章节介绍如何使用fast_ae做通路快启，快速收敛曝光。

    • 代码流程

    • sample使用指南

    代码流程

    1. 使用sample_comm_vi_start_sensor启动mipi_rx和时钟。
    2. 调用sensor接口pfn_set_init配置sensor初始化序列和曝光，以及ae快速收敛使能。
    3. 通路初始化(不包含sensor)。
    4. 待通路收敛后，调用hi_mpi_isp_query_exposure_info，获取并打印收敛后曝光参数。
    5. 保存码流，退出通路。

    sample使用指南

    快速收敛曝光需区分有光敏快速收敛和无光敏快速收敛。

    • 有光敏快速收敛包含曝光初始值的查询和AE快速收敛算法。

    • 无光敏快速收敛只包含AE快速收敛算法。

    • 有光敏快速收敛

    • 无光敏快速收敛

    有光敏快速收敛
    1. 不同照度下，执行fast_ae获取收敛后状态，将光敏输出与fast_ae结果绑定，绘制成曝光表。
    2. 使用快启时，通过光敏值输出，查询曝光表中对应的曝光结果。
    3. 将曝光结果作为初始值用于fast_ae的输入实现快速收敛。
    无光敏快速收敛

    在最常用的场景下，执行fast_ae获取收敛后状态，将该结果作为fast_ae初始值。

    1. 见lsc_online_cali.c文件，sample_lsc_usage函数查看sample执行指令格式。

    5. 最终调用mpi接口ss_mpi_isp_mesh_shading_calibration完成标定，涉及算法的描述可参考《ISP开发参考》“Mesh Shading”章节和《ISP图像调优指南》“Mesh Lens Shading”章节。

    1. Canny,<complete>:0, part canny;1,complete canny. (FILE->IVE->FILE)

      Canny 操作是一种经典的边缘检测算法，Sample中共提供了两种不同的实现方式，主要区别在于是否包含了完整的Canny步骤。Sample中读取灰度图进行边缘检测，得到运算后的检测结果图并保存为文件，两种Canny边缘提取流程如图1所示。

      图 1 Canny边缘提取

      • part canny 仅实现了Canny算法的部分步骤，只进行了滤波和梯度计算，省略了极大值抑制和双阈值检测。特点是实现简单，计算速度快，边缘检测效果较差，容易出现噪声或断裂的边缘，适用于对实时性要求高，但对边缘精度要求不高的场景。

        核心步骤：

        ①梯度计算 ss_mpi_ive_mag_and_ang；

        ②阈值化处理 ss_mpi_ive_threshold_u16。

        part canny边缘检测效果如图2所示。

        图 2 part canny

        核心步骤：

        ① ss_mpi_ive_canny_hys_edge 灰度图的Canny边缘提取的前半部：求梯度、计算梯度幅值幅角、磁滞阈值化及非极大抑制。

        ② ss_mpi_ive_canny_edge 灰度图的Canny边缘提取的后半部：连接边缘点，形成Canny边缘图。

    SVP_NPU

    SVP_NPU共提供了6个sample，主要包括代表性智能模型的示例代码，以及一些NPU主要功能的接口调用流程。

    Sample代码中提供了NPU通用智能模型接口的调用流程，接口调用如图1所示。

    图 1 通用模型推理流程

    SVP_NPU Sample的基本调用流程都是一致的，主要包括ACL初始化、模型加载推理和资源释放三个方面。下面对各个Sample的特点进行介绍：

    1. svp_acl_resnet50

      resnet50模型示例代码，主要演示了NPU加载resnet50模型，并推理单张图片的过程。

      应用场景：NPU 分类网模型的加载推理，以及如何处理分类网模型的推理结果。

      核心代码：sample_common_svp_npu_output_classification_result，通过获取分类网输出结果，对每种类的分值进行排序，并输出分值最高的前五个分类。

    2. svp_acl_resnet50_multi_thread

      NPU推理多线程示例代码，在svp_acl_resnet50的基础上，加入了多线程的实现。

      核心代码：sample_svp_npu_acl_model_execute_multithread，通过创建多个NPU task, 将任务分发给不同线程，从而达到多线程调用NPU任务的效果。

    3. svp_acl_resnet50_dynamic_batch_with_mem_cached

      动态batch示例代码，主要演示了如何调用接口动态配置batch，并完成多batch推理。svp_acl_resnet50输入数据为一张单batch图片，该用例在svp_acl_resnet50基础上，通过配置模型batch_size，使模型每次处理图片的数量达到8张。同时，该sample演示了如何配置NPU task是否带cache调用。

      核心参数配置：

      g_svp_npu_task[0].cfg.max_batch_num = 8;
g_svp_npu_task[0].cfg.is_cached = TD_TRUE;

      核心代码：sample_common_svp_npu_set_dynamic_batch， 通过调用svp_acl_mdl_set_dynamic_batch_size接口，配置模型batch_num。batch_num值约束请查看《ATC工具使用指南》中batch_num参数说明。

    4. svp_acl_lstm

      lstm模型实例代码，主要演示了如何配置lstm模型推理所需的参数。lstm具有两路输入，且lstm模型推理需要额外配置total_t参数(Recurrent网络包含LSTM/RNN/GRU层每一句话的最大帧数)，该sample演示了lstm模型推理的参数配置。

      特殊参数配置：

      g_svp_npu_task[0].cfg.total_t = 3;

      核心代码：svp_acl_mdl_set_total_t，调用ACL接口配置模型所需的total_t参数。

    5. svp_acl_preemption

      模型抢占示例代码，主要演示了当开启模型抢占时，高优先级的模型推理任务可以打断低优先级的推理任务，从而抢占NPU资源优先执行。该sample中加载的模型为可抢占模型（模型是否可被抢占参考《ATC工具使用指南》“--hwts_preemption_enable”章节）, NPU通过两次加载该模型，并配置其中一个模型的抢占级别更高，进而使高优先级的模型可以抢占低优先级的模型，获取对应NPU资源优先执行。

      核心代码：sample_svp_npu_set_model_prior_info，通过配置抢占参数，使分别加载进来的模型拥有不同的抢占优先级，进而在推理任务开始时，优先执行抢占优先级高的模型推理任务

      核心参数示例：

      g_svp_npu_model.prior_cfg.priority = 2; // 模型优先级值
g_svp_npu_model.prior_cfg.prior_preemp_en = 1; // 是否开启优先级抢占
g_svp_npu_model.prior_cfg.prior_up_step_timeout = 1200; // 优先级提升超时值

    6. yolov8 (VI->VPSS->SVP_NPU->VGS->VENC)

      yolov8模型示例代码，主要演示了如何全流程跑通VI、VPSS、NPU推理、VGS、VENC，为实际应用场景提供了接口调用的流程示例。整个流程涉及到VI, VPSS, VB, NPU, VGS, VENC, VO多个模块的协同工作，各个模块调用流程如图2所示。

      图 2 yolov8 sample流程图

      主要流程：

      • VI模块进行摄像头传感器流输入。
      • 视频流会送入VPSS模块进行图像处理，这里将原始流截取出yuv420P图像，并resize成模型需要用到的图像大小。
      • VB模块负责管理缓冲池，接受来自VPSS输出信号。
      • NPU不断从VB缓冲池中获取对应帧，创建任务并进行推理。
      • VGS模块根据推理结果，在展示帧上进行画框。
      • VENC模块将展示帧进行编码。

      核心代码：sample_common_svp_npu_start_vi_vpss_venc，示例代码中描述了如何配置vi参数、创建vb、启动vi、绑定vpss、启动vpss、vpss连接vb、启动venc等。

    host_uvc

    host_uvc在板端做USB HOST时，从外接UVC摄像头中读取YUV/编码数据流，并保存为文件，其中不涉及MPP媒体接口。

    *代码简介*

    • host_uvc代码按V4L2标准打开/dev/videoX设备后，通过ioctl方式查询设备能力、添加buffer、设置媒体格式和分辨率等操作，循环读取视频流数据后存为文件。由于不依赖第三方库，用户也可以移植开源代码来实现同样功能。
    • host_uvc.c中sample_uvc_video_save_image()拿到内核返回的帧缓冲buffer后，立即进行保存文件操作，可在此处进行修改，禁用存文件功能，对接其他业务。

    *运行示例*

    1. 先将USB子系统切换为HOST主机模式：

      echo host     > /proc/wing-usb/10300000.usb20drd/mode

    2. 接上外部UVC摄像头，用下面命令查看其支持的格式和分辨率：

      ./sample_host_uvc /dev/video0 --enum-formats

    3. 根据支持的格式和分辨率，拉取视频流并保存文件，参考下列命令：

      ./sample_host_uvc /dev/video0 -fMJPEG -s1920x1080 -Fstream_1920x1080.mjpg
./sample_host_uvc /dev/video0 -fH264  -s1920x1080 -Fstream_1920x1080.h264
./sample_host_uvc /dev/video0 -fH265  -s1920x1080 -Fstream_1920x1080.h265
./sample_host_uvc /dev/video0 -fYUYV  -s1920x1080 -Fraw_1920x1080.yuyv
./sample_host_uvc /dev/video0 -fNV21  -s1920x1080 -Fraw_1920x1080.nv21
./sample_host_uvc /dev/video0 -fNV12  -s1920x1080 -Fraw_1920x1080.nv12

      注意：保证当前目录的可用空间足够大。

    4. 将上述操作生成的YUV或码流文件权限改为0666，然后复制到电脑上，用PotPlayer、VLC、YUV Player等工具查看图像是否正常。

    下面常见问题的处理方法详细参考代码目录sample/host_uvc/readme.txt.

    1. sample可能会因系统内存不足被杀掉，可以通过增大OS内存和减小MMZ内存来解决；

    代码简介

    基于V4L2框架，uvc_app可以编译出两个sample程序。

    • sampel_uvc_v4l2支持传统的纯V4L2方案，即通过VIDEO_IOCTL_DQUEUE_BUF/VIDEO_IOCTL_QUEUE_BUF两个ioctl系统调用将视频流数据复制给内核并发送给USB HOST，此种方式需要复制一次，效率不高。
    • sample_uvc对视频流的发送方式进行了定制优化，基于新增的ot_uvc.ko和mpi_uvc_xxx接口支持三类送视频数据输入模式：零拷贝绑定、用户态零拷贝送stream/frame、用户态拷贝自有数据流。

    两个程序在V4L2控制方面的实现是相同的，主要差异在于发送视频数据的方式。另外V4L2程序单路场景可支持still image抓图功能。

    5. 零拷贝sample数据输入模式

      不同于sample_uvc_v4l2使用ioctl系统调用将缓冲区从用户态送进内核驱动，零拷贝的sample_uvc通过ot_uvc.ko和UVC mpi接口，使用了定制的视频流传输通道，目前支持三类方式，可以通过命令行参数进行修改。

      ./sample_uvc [DEVICE_COUNT] [DATA_MODE]
      • DEVICE_COUNT：UVC设备数量（设备号对应UVC通道号），跟ConfigUVC.sh用到的${UVC_DEVICE_CNT}要保持一致。

      • DATA_MODE：UVC视频流数据输入模式，现在支持0-2三种选择：

        • 0：UVC_MPP_BIND_UVC 绑定模式，VPSS或VENC可以与UVC绑定，内核态零拷贝绑定直传视频数据；
        • 1：UVC_SEND_YUV_FRAME/UVC_SEND_VENC_STREAM，用户态从VPSS/VENC拿到的frame/stream以零拷贝方式用mpi_uvc_send_frame/mpi_uvc_send_stream接口中送UVC驱动；该模式可以在把视频数据发送给UVC接口之前，将视频数据进行网络传输或存储；
        • 2：UVC_SEND_USER_STREAM对于编码码流，可以从用户指定的任意有效地址上拷贝码流，便于定制添加私有数据。在sample里YUV格式仍采用绑定方式，虽然可以用mpi_uvc_send_user_stream传送YUV数据，由于拷贝方式效率较低所以不推荐。

        如果要修改数据输入模式，需要修改sample_uvc的第2个命令行参数为0、1、2之一即可，然后重启运行runUVC.sh。

    sample_vie_wdr

    1. 使用场景

      WDR（Wide Dynamic Range，宽动态范围）是一种图像处理技术，主要用于改善在高对比度光照环境下拍摄的图像质量。在一些场景下，比如室内室外光线差异极大的地方，或者强光源直射的地方，普通的摄像头可能会因为过曝或欠曝而无法清晰地捕捉到所有细节。WDR技术通过结合不同曝光时间的多张图像来生成一张最终的图像，在这张图像中，亮部和暗部的细节都能得到较好的保留。这样就能使得在极端光照条件下也能获得更加自然、清晰的图像效果。

      线性模式与WDR模式效果对比：

    2. 使用说明

      • load脚本时需要使用参数profile=1，以20s为例，ko加载命令为 ./load3516cv610_20s_debug -a -profile 1;
      • Hi3516CV610-10B默认的VICAP及ISP0频点较低，若需要接入WDR时序，需要更改SYS_CFG模块的HI3516CV610_10B_WDR宏值以接入WDR时序，详见《SYS_CFG 配置指南》。
      • 默认SENSOR HY006_3814_0011_MIPI_4M_30FPS_10BIT不支持WDR模式，但是sample中预留HY006_3814_0011_MIPI_4M_30FPS_10BIT_WDR2TO1配置，若用户接入一个可支持WDR时序的SENSOR，可根据预留配置做适配。主要适配点包括（搜索关键字HY006_3814_0011_MIPI_4M_30FPS_10BIT_WDR2TO1适配即可）：

    sample_vie_fpn

    1. 使用场景

      固定模式噪声（Fixed Pattern Noise，FPN）是一种常见的图像传感器噪声类型，这种噪声通常是由于传感器内部的物理缺陷或不均匀性造成的。FPN可能导致图像中出现明显的条纹或斑点，影响图像的清晰度和对比度。Hi3516CV610提供去FPN功能，去除SENSOR产生的固定噪声，图像效果更佳。
